# ADR-0003: Web UI の「終了」を「保存してリセット」に置き換える

- ステータス: Accepted
- 日付: 2026-06-09
- 関連: なし

## コンテキスト

これまで Web UI の右上にあった「終了 Q」ボタンは、押すと議事録を保存してから uvicorn サーバーごと落とし、ブラウザには「保存先のパスをコピーしてタブを閉じてください」というモーダルを表示する仕組みだった。

実運用では以下の不便があった：

1. **会議を連続でやるとき毎回サーバー再起動が必要**: 1 つ会議を終えるたびに CLI から `meeting-transcriber --web` を再起動 → ブラウザを開き直すサイクルが煩雑
2. **Whisper モデルの再ロードが重い**: medium / large-v3 を CUDA でロードする時間は数十秒〜数分。会議のたびに支払うコストとしては大きい
3. **「終了 = タブを閉じろ」というメッセージが直感に反する**: 通常の Web アプリは「保存したら次の作業に進める」が期待値
4. **開始の概念がない**: 既存の UI は「サーバー起動 = 即録音開始」で、明示的な「会議を始める」操作がなかった。一時停止/再開は別概念

## 決定

### 1. 「終了 Q」を「保存してリセット R」に置き換える

押下時の挙動：

1. 録音を停止 (`recorder.stop()`)
2. 現在の transcripts と minutes を保存
3. transcripts / minutes / chat_history / `_chat_last_transcript_index` をクリア
4. backend の `session_id` を新規発行 (prompt cache を新会議扱いに)
5. 結果を `{'type': 'reset', 'output_path': ...}` でブロードキャスト
6. **uvicorn は落とさない**

サーバー自体を落とすのは Ctrl-C に集約 (ADR 内部の運用判断、別途実装済み: 1 回目 graceful shutdown、2 回目 / 8 秒タイムアウトで `os._exit`)。

### 2. 「開始 G」ボタンを新設

録音が停止中 (`recorder.is_recording() == False`) のときだけ表示。押下で：

- 新しい `start_time` を発行
- `MinutesUpdater` を再構築 (新セッションディレクトリ)
- `recorder.start()`

`AudioRecorder.is_recording()` を新設し、状態に応じて UI 側で「開始 G」⇔「一時停止 P / 再開 P」を切り替える。

### 3. 保存通知をトースト UI に変更

地味なログ 1 行ではなく、画面上部に出てくる **トースト** で通知する：

- 保存成功: 緑帯 + パス + 「パスをコピー」ボタン + 8 秒で自動消失
- 保存対象なし (transcripts が空): 黄帯 + 4 秒で自動消失
- 保存失敗: 赤帯 + 手動で閉じるまで残る

トーストは `document.createElement` + `textContent` + `addEventListener` で構築し、`innerHTML` に動的値を埋めない (XSS 対策)。

### 4. キーボードショートカット

- `R` キー: 保存してリセット
- `G` キー: 開始
- 既存の `P` (一時停止), `U` (差分更新), `F` (フル更新), `S` (クイック保存) は維持

## 影響

- **連続会議運用が楽になる**: モデル再ロード不要で次の会議をすぐ始められる
- **session ディレクトリの命名**: `_handle_start` 時点の `start_time` で `MinutesUpdater` を再生成するため、ファイル名タイムスタンプは「録音開始時刻」になる (以前は「サーバー起動時刻」だった)
- **API 互換**: `/api/quit` は残しつつ実質非推奨。`/api/reset` と `/api/start` を新規追加
- **WebSocket イベント**: `reset` イベントを新設。フロント側で受けてパネルをクリア + トースト表示
- **テスト**: 録音 → 保存リセット → 再開 → 保存リセット の 2 サイクルで session ディレクトリが正しく切り替わることを smoke 確認済み

## 代替案

### 代替案 A: 「終了」を残しつつ「リセット」を別ボタンで追加

- メリット: 既存ワークフローを壊さない
- デメリット: ボタンが増えて画面が混雑。「終了って何のため？」がさらに不明確に
- → 採用しない (機能を絞る方が UI として正しい)

### 代替案 B: 自動セッション切り替え (録音中の長時間沈黙で自動 reset)

- メリット: 操作不要
- デメリット: 沈黙の閾値が会議によって違うので誤動作リスク。明示操作の方が安心
- → 採用しない

### 代替案 C: 既存「終了」+ サーバー再起動の自動化

- メリット: 状態管理が単純
- デメリット: Whisper モデル再ロードコストが残る
- → 採用しない
